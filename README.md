## Why `mongol-font-shaper`?

Traditional Mongolian (Hudum) digital texts span more than three decades of competing standards and vendor font conventions—**Unicode UTN #57**, **GB/T 25914-2023**, **GB/T 25914-2010**, **Menksoft (v1.x / v2.0)**, **Oyun (v1.x / v2.002+)**, **Delehi (v1.x / v3.0)**, **Microsoft Mongolian Baiti**, **Menk-PUA (`U+E234..`)**, **ZvvnMod PUA (`U+E000..`)**, **Z52 (`U+1877..` + PUA)**, and 1990s **ASCII-mapped fonts**.

The **same Unicode codepoint sequence** often renders completely different visual shapes across fonts (for example, `U+202F + ᠶᠢᠨ` `-yin`, `U+202F + ᠤᠨ` `-un`, `U+182D` feminine `GA` before consonants, or `FVS1..FVS3` assignments). Only the **actual font file used by the author** knows what visual shape was truly intended on screen.

`mongol-font-shaper` solves this cleanly in pure Rust:

1. **Arbitrary External Font Shaping (`FontShaper`)**: Loads any `.ttf` / `.otf` / `.ttc` font file via pure-Rust HarfBuzz (`harfrust` — supporting OpenType `GSUB`, Apple `AAT/morx`, and pure `cmap` PUA/Z52/ASCII fonts) and maps glyphs through human-editable family-level `*.profile.json` configurations.
2. **Three Canonical Outputs** (powered by `mongol-norm` with `default-features = false`):
   - `Vec<PositionedWrittenUnit>` (`FontShaper::shape_positioned`) — exact graphic written units with `isol` / `init` / `medi` / `fina` / `control` positions;
   - `Vec<WrittenUnit>` (`FontShaper::shape_units`) — canonicalized `WrittenUnit` sequence matching `mongol_norm::Shaper::shape`;
   - `String` (`FontShaper::normalize_text`) — canonical **UTN #57** Mongolian Unicode text preserving spaces, punctuation, digits, CJK, Cyrillic, and Latin spans verbatim, plus explicit `ZWJ` (`U+200D`) dictionary affixes.
3. **Multi-Font Defect Detection & Corpus Voting (`FontPool`)**: Automatically eliminates wrong fonts via `.notdef` (`NotDef`), unconsumed dotted-circle variation selectors (`VisibleFvs`), and broken word-boundary joining teeth (`ChainPositionBreak`), and locks the exact font of an entire dictionary or book via `FontPool::detect_corpus`.
4. **Profile Pre-Generator & Local Visual Calibration Studio (`init-map`)**: Pre-generates family-level `*.profile.json` files from any font—including nameless `post v3.0` `.otf`/`.ttf` black-box fonts via cluster-anchored `ShapingProbe`s—and optionally renders an offline interactive vertical-Mongolian SVG calibration webpage.

## Family-Level `FontProfile` Design (No Brittle SHA-256 Hashes)

Instead of per-file SHA-256 hashes (where Menksoft, FangZheng, Delehi, or Oyun ship 20–90 stylistically different weights and calligraphic fonts sharing the exact same glyph naming and `GSUB` architecture), `mongol-font-shaper` uses **portable family-level `*.profile.json` files** that resolve glyph IDs (`GID`) dynamically in four priority tiers:

1. **`glyph_names`** — Matches `post` / `CFF` glyph names (e.g. `uni1820.A.isol`, `u1820.A.isol`, `U1820_ISOL`, `a_1.isol`) across all weights of a vendor family.
2. **`codepoints`** — Resolves `cmap` entries directly (`U+E234..` Menk-PUA, `U+E000..` ZvvnMod, `U+1877..` Z52, or legacy ASCII).
3. **`probes` (`ShapingProbe`)** — Shapes canonical miniature Mongolian contexts at load time and matches `(cluster, end_cluster)` spans, binding **100% of contextual glyphs even on nameless `post v3.0` `.otf` / `.ttf` fonts** (such as Noto OTF, `DraftNew-Regular.otf`, and Microsoft `Mongolian Baiti`).
4. **`gid` + `overrides`** — Optional fallback GID or per-font PostScript-name override for rare single-font quirks.

## CLI Usage

### 1. Build

```bash
cargo build --release
```

### 2. Shape & Normalize Text (`shape`)

```bash
# Built-in UTN #57 profile -> Canonical UTN #57 Unicode text
mongol-font-shaper shape \
  --font tests/fonts/NotoSansMongolian-Regular.ttf \
  --profile utn57 \
  --format text \
  "ᠮᠣᠩᠭᠣᠯ ᠤᠨ ᠪᠠᠶᠢᠨ᠎ᠠ"

# Output canonical WrittenUnit sequence ("M+O+A+G+N+N+O+L+Mvs+O+A ...")
mongol-font-shaper shape \
  --font tests/fonts/NotoSansMongolian-Regular.ttf \
  --profile utn57 \
  --format units \
  "ᠮᠣᠩᠭᠣᠯ ᠤᠨ ᠪᠠᠶᠢᠨ᠎ᠠ"

# Shape with any external vendor font (on-the-fly '--profile auto' or saved '*.profile.json')
mongol-font-shaper shape \
  --font "/path/to/OyunQaganTig.ttf" \
  --profile auto \
  --format positioned \
  "ᠠᠬ᠎ᠠ ᠶᠢᠨ"
```

### 3. Multi-Font Detection & Corpus Voting (`detect`)

```bash
# Single sentence / word encoding discrimination
mongol-font-shaper detect \
  --pool "oyun2023=/path/to/OyunQaganTig.ttf:auto" \
  --pool "menk2010=/path/to/MQG8F02.ttf:auto" \
  --pool "baiti=/path/to/monbaiti.ttf:auto" \
  "ᠭᠡᠷ ᠲᠦ᠍"

# Corpus-level batch voting across an entire dictionary or book (--corpus)
mongol-font-shaper detect \
  --corpus \
  --pool "utn57=tests/fonts/NotoSansMongolian-Regular.ttf:utn57" \
  --pool "oyun2023=/path/to/OyunQaganTig.ttf:auto" \
  --pool "menk2010=/path/to/MQG8F02.ttf:auto" \
  --pool "baiti=/path/to/monbaiti.ttf:auto" \
  --input "/path/to/dictionary_entries.txt"
```

> **How Multi-Font Detection Works**:
> - **Consensus (`Exact`)**: ~75% of common words render identically across Unicode Mongolian fonts, yielding an instant canonical output without worrying which font was used.
> - **Defect Elimination (`Exact`)**: PUA / Z52 codepoints, GB2023-specific `FVS` combinations (`VisibleFvs`), or Baiti word-end medial breaks (`ChainPositionBreak`) immediately eliminate incompatible fonts.
> - **Ambiguity Notice (`Ambiguous`)**: If an isolated word is clean (`0` defects) under two standards that intentionally assign different shapes (e.g. GB2023 vs GB2010 `-yin` / `-un`), `detect` reports `Ambiguous` and advises running `--corpus` on the surrounding document.

### 4. Pre-Generate Editable Profile & Visual Calibration HTML (`init-map` & `inspect`)

```bash
# Inspect font SFNT tables, glyph names, PUA ranges, and inferred encoding class
mongol-font-shaper inspect "/path/to/FontFile.ttf"

# Pre-generate a human-editable family profile JSON + local offline SVG calibration HTML
mongol-font-shaper init-map "/path/to/FontFile.ttf" \
  --id my-family \
  --output profiles/my-family.profile.json \
  --html var/calibration/my-family.html
```

## Rust Library Quick Start

```rust
use mongol_font_shaper::{DetectionStatus, FontPool, FontProfile, FontShaper};

fn main() -> Result<(), mongol_font_shaper::Error> {
    // 1. Load built-in UTN #57 profile + any .ttf / .otf / .ttc font
    let profile = FontProfile::builtin_utn57();
    let shaper = FontShaper::from_path("tests/fonts/NotoSansMongolian-Regular.ttf", 0, &profile)?;

    // Output 1: Vec<PositionedWrittenUnit>
    let positioned = shaper.shape_positioned("ᠮᠣᠩᠭᠣᠯ ᠤᠨ")?;
    assert!(positioned.diagnostics.is_clean());

    // Output 2: Vec<WrittenUnit> (matches `mongol_norm::Shaper::shape`)
    let units = shaper.shape_units("ᠮᠣᠩᠭᠣᠯ ᠤᠨ")?;
    println!("WrittenUnits: {:?}", units.value);

    // Output 3: Canonical UTN #57 String (preserves mixed CJK/English/punctuation)
    let normalized = shaper.normalize_text("《ᠮᠣᠩᠭᠣᠯ ᠤᠨ ᠪᠢᠴᠢᠭ》 — UTN #57")?;
    println!("Normalized: {}", normalized.value);

    // Multi-font pool detection
    let mut pool = FontPool::new();
    pool.push("utn57", shaper);
    let result = pool.detect_text("ᠮᠣᠩᠭᠣᠯ")?;
    assert_eq!(result.status, DetectionStatus::Exact);

    Ok(())
}
```
