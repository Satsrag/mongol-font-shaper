## Why `mongol-font-shaper`? / 为什么需要 `mongol-font-shaper`？

Traditional Mongolian (Hudum) digital texts span more than three decades of competing standards and vendor font conventions—**Unicode UTN #57**, **GB/T 25914-2023**, **GB/T 25914-2010**, **Menksoft (v1.x / v2.0)**, **Oyun (v1.x / v2.002+)**, **Delehi (v1.x / v3.0)**, **Microsoft Mongolian Baiti**, **Menk-PUA (`U+E234..`)**, **ZvvnMod PUA (`U+E000..`)**, **Z52 (`U+1877..` + PUA)**, and 1990s **ASCII-mapped fonts**.  
The **same Unicode codepoint sequence** often renders completely different visual shapes across fonts (for example, `U+202F + ᠶᠢᠨ` `-yin`, `U+202F + ᠤᠨ` `-un`, `U+182D` feminine `GA` before consonants, or `FVS1..FVS3` assignments). Only the **actual font file used by the author** knows what visual shape was truly intended on screen.

传统蒙古文（胡都木文）数字化语料横跨三十余年的多种编码标准与厂商字体流派——包括 **Unicode UTN #57**、**GB/T 25914-2023（新国标）**、**GB/T 25914-2010（旧国标）**、**蒙科立 Menksoft（v1.x / v2.0）**、**奥云 Oyun（v1.x / v2.002+）**、**德力海 Delehi（v1.x / v3.0）**、**微软 Mongolian Baiti**、**蒙科立 PUA 私用区（`U+E234..`）**、**昭乌达 ZvvnMod 私用区**、**Z52 编码**以及上世纪 90 年代的 **ASCII 映射老字体**。  
**完全相同的一串 Unicode 码位**在不同字体下往往渲染出截然不同的字形（例如 `U+202F + ᠶᠢᠨ` 属格后缀、`U+202F + ᠤᠨ` 领格后缀、阴性词辅音前的 `GA` 以及 `FVS1..FVS3` 变体选择符语义）。只有**还原作者当年录入时所使用的真实字体排版结果**，才能无损提取真实的书面字形语义。

`mongol-font-shaper` solves this cleanly in pure Rust / `mongol-font-shaper` 用纯 Rust 架构彻底解决这一痛点：

   通过纯 Rust 版 HarfBuzz（`harfrust`，原生支持 OpenType `GSUB`、Apple `AAT/morx` 状态机及纯 `cmap` 映射字体）加载任意 `.ttf` / `.otf` / `.ttc` 字体，并结合人类可读可编辑的家族级 `*.profile.json` 配置还原书面字形单元。
2. **Three Canonical Outputs / 三种标准输出形态**（powered by `mongol-norm` `default-features = false`）：
   - `Vec<PositionedWrittenUnit>` (`FontShaper::shape_positioned`) — exact graphic written units with `isol`/`init`/`medi`/`fina`/`control` positions / 带词首中尾位置信息的精确书面字形单元序列；
   - `Vec<WrittenUnit>` (`FontShaper::shape_units`) — canonicalized `WrittenUnit` sequence matching `mongol_norm::Shaper::shape` / 与 `mongol-norm` 完全一致的标准字形单元序列；

## Family-Level `FontProfile` Design / 家族级 `FontProfile` 设计（告别 SHA-256 绑定）

Instead of brittle per-file SHA-256 hashes (where Menksoft, FangZheng, Delehi, or Oyun ship 20–90 stylistically different weights/calligraphic fonts sharing the exact same glyph naming & `GSUB` architecture), `mongol-font-shaper` uses **portable family-level `*.profile.json` files**.  
蒙科立、方正、德力海、奥云等字库往往一套标准包含数十款不同字重与美术字体，其内部字形命名与 `GSUB` 变形逻辑高度一致。因此本项目摒弃脆弱的“单文件 SHA-256 绑定”，采用**跨字重通用的家族级 `*.profile.json` 配置**，按 4 级优先级动态绑定字形 ID（`GID`）：

1. **`glyph_names`** — Matches `post` / `CFF` glyph names (e.g. `uni1820.A.isol`, `u1820.A.isol`, `U1820_ISOL`, `a_1.isol`). / 匹配字体内部字形名（通吃同厂商全系字体）。
2. **`codepoints`** — Resolves `cmap` entries directly (`U+E234..` Menk-PUA, `U+E000..` ZvvnMod, `U+1877..` Z52, or legacy ASCII). / 直接通过 `cmap` 码位解析 PUA / Z52 / 老编码字形。
3. **`probes` (`ShapingProbe`)** — Shapes canonical miniature Mongolian contexts at load time and matches `(cluster, end_cluster)` spans, binding **100% of contextual glyphs even on nameless `post v3.0` `.otf` / `.ttf` fonts** (such as Noto OTF, `DraftNew-Regular.otf`, and Microsoft `Mongolian Baiti`). / 加载字体时动态运行微型探针词并校验字符簇区间，**即使面对完全剥离字形名的 `post v3.0` 黑盒字体也能 100% 精准绑定**。
4. **`gid` + `overrides`** — Optional fallback GID or per-font PostScript-name override for rare single-font quirks. / 兜底 GID 与按字体内部名称匹配的局部覆盖补丁。

## CLI Usage / 命令行使用指南

### 1. Build / 编译安装

```bash
cargo build --release
```

### 2. Shape & Normalize Text (`shape`) / 塑形与 UTN #57 转换

```bash
# Built-in UTN #57 profile -> Canonical UTN #57 Unicode text
# 使用内置 UTN #57 配置，输出标准 UTN #57 蒙古文文本
mongol-font-shaper shape \
  --font tests/fonts/NotoSansMongolian-Regular.ttf \
  --profile utn57 \
  --format text \
  "ᠮᠣᠩᠭᠣᠯ ᠤᠨ ᠪᠠᠶᠢᠨ᠎ᠠ"

# Output canonical WrittenUnit sequence ("M+O+A+G+N+N+O+L+Mvs+O+A ...")

  --font tests/fonts/NotoSansMongolian-Regular.ttf \
  --profile utn57 \
  --format units \
  "ᠮᠣᠩᠭᠣᠯ ᠤᠨ ᠪᠠᠶᠢᠨ᠎ᠠ"

# Shape with any external vendor font (on-the-fly '--profile auto' or saved '*.profile.json')
# 使用任意外部商业/第三方字体塑形（支持 '--profile auto' 自动推断或加载预生成的 '*.profile.json'）
mongol-font-shaper shape \
  --font "/path/to/OyunQaganTig.ttf" \

  --format positioned \
  "ᠠᠬ᠎ᠠ ᠶᠢᠨ"
```

### 3. Multi-Font Detection & Corpus Voting (`detect`) / 多字体错码筛查与语料投票

```bash
# Single sentence / word encoding discrimination
# 单句/单词多字体判别（自动剔除触发 .notdef / 显式 FVS / 连写断裂的错误字体）
mongol-font-shaper detect \
  --pool "oyun2023=/path/to/OyunQaganTig.ttf:auto" \
  --pool "menk2010=/path/to/MQG8F02.ttf:auto" \
  --pool "baiti=/path/to/monbaiti.ttf:auto" \
  "ᠭᠡᠷ ᠲᠦ᠍"

# Corpus-level batch voting across an entire dictionary or book (--corpus)
# 整本词典或多行语料批量投票（一锤定音锁定整本书的真实录入字体标准）
mongol-font-shaper detect \
  --corpus \
  --pool "utn57=tests/fonts/NotoSansMongolian-Regular.ttf:utn57" \
  --pool "oyun2023=/path/to/OyunQaganTig.ttf:auto" \
  --pool "menk2010=/path/to/MQG8F02.ttf:auto" \
  --pool "baiti=/path/to/monbaiti.ttf:auto" \
  --input "/path/to/dictionary_entries.txt"
```

> **How Multi-Font Detection Works / 多字体判别原理说明**：
> - **Consensus (`Exact`) / 零分歧共识**：~75% of common words render identically across Unicode Mongolian fonts -> instant canonical output without worrying which font was used. / 约 75% 常规词汇在各家 Unicode 字体下产出完全相同的标准结果，直接零分歧输出。
> - **Defect Elimination (`Exact`) / 错码排除**：PUA / Z52 codepoints, GB2023-specific `FVS` combinations (`VisibleFvs`), or Baiti word-end medial breaks (`ChainPositionBreak`) immediately eliminate incompatible fonts. / 私用区码位、特定国标 `FVS` 组合或词尾连写断裂会自动淘汰不匹配的字体。
> - **Ambiguity Notice (`Ambiguous`) / 同码异形提示**：If an isolated word is clean (`0` defects) under two standards that intentionally assign different shapes (e.g. GB2023 vs GB2010 `-yin` / `-un`), `detect` reports `Ambiguous` and advises running `--corpus` on the surrounding document. / 若孤立短词在两种标准下均合法但字形不同，工具会诚实标记 `Ambiguous`，建议结合整篇文档运行 `--corpus` 投票锁定唯一字体。

## Rust Library Quick Start / Rust 库快速上手

```rust
use mongol_font_shaper::{DetectionStatus, FontPool, FontProfile, FontShaper};

fn main() -> Result<(), mongol_font_shaper::Error> {
    // 1. Load built-in UTN #57 profile + any .ttf / .otf / .ttc font
    // 1. 加载内置 UTN #57 家族配置与字体文件
    let profile = FontProfile::builtin_utn57();
    let shaper = FontShaper::from_path("tests/fonts/NotoSansMongolian-Regular.ttf", 0, &profile)?;

    // Output 1: Vec<PositionedWrittenUnit>
    let positioned = shaper.shape_positioned("ᠮᠣᠩᠭᠣᠯ ᠤᠨ")?;
    assert!(positioned.diagnostics.is_clean());

    // Output 2: Vec<WrittenUnit> (matches `mongol_norm::Shaper::shape`)
    let units = shaper.shape_units("ᠮᠣᠩᠭᠣᠯ ᠤᠨ")?;
    println!("WrittenUnits: {:?}", units.value);

    // Output 3: Canonical UTN #57 String (preserves mixed CJK/English/punctuation)
    let normalized = shaper.normalize_text("《ᠮᠣᠩᠭᠣᠯ ᠤᠨ ᠪᠢᠴᠢᠭ》 — UTN #57")?;
    println!("Normalized: {}", normalized.value);

    // Multi-font pool detection
    // 多字体池判别
    let mut pool = FontPool::new();
    pool.push("utn57", shaper);
    let result = pool.detect_text("ᠮᠣᠩᠭᠣᠯ")?;
    assert_eq!(result.status, DetectionStatus::Exact);

    Ok(())
}
```
